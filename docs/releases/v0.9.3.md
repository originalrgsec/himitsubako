# v0.9.3 — Release Pipeline Fix (publish action)

**Released:** 2026-11-02
**Sprint:** none (out-of-band maintenance patch)

## Summary

v0.9.2 passed `verify` and `build`, but the PyPI publish job (run
41521791412) failed. `pypa/gh-action-pypi-publish@v1.13.0` runs its own
bundled twine 6.1.0 for `twine check`, so the project's own twine 7.0.0
upgrade (v0.9.2) did not reach that step, and the action rejected the
Metadata-Version 2.5 wheel. Nothing was published to PyPI for v0.9.1 or
v0.9.2, and no GitHub Release was created for either.

v0.9.3 ships the v0.9.1 dependency security fixes and the v0.9.2 twine
upgrade unchanged.

## Changes

| Component | Old | New | Notes |
|-----------|-----|-----|-------|
| pypa/gh-action-pypi-publish (release.yml, testpypi.yml) | v1.13.0 | v1.14.3 | Bundles twine 7.0.0 (Metadata-Version 2.5 support added in v1.14.2). Released 2026-10-20, past the 7-day quarantine. |

The action stays tag-pinned per the existing Docker-container-action
exception in the `release.yml` header.

## Superseded tags

`v0.9.1` and `v0.9.2` remain on the remote with no Release and no PyPI
artifacts. They were left in place rather than deleted (deleting
published refs is a gated operation).
